# Neon Mary on Windows 11

## What is actually themeable

Windows 11 theming splits into three tiers with very different support levels.
This directory covers the first two — both documented, per-user, and
reversible. It deliberately ships nothing that requires patching the OS.

| Layer | Themeable? | How |
|---|---|---|
| Desktop wallpaper | Yes | `.theme` file |
| Light / dark mode (apps + system) | Yes | `.theme` + registry |
| Accent colour — taskbar, Start, focus rings, title bars | Yes | registry |
| Terminal colours | Yes | `../terminals/<variant>/<mode>/windows-terminal.json` |
| **Window frame chrome, Start flyout, Explorer styling** | **No** | needs a patched visual style |

That last row is the honest limit. Restyling actual window frames requires a
`.msstyles` visual style, and Windows refuses to load unsigned ones. Getting
around that means installing a signature bypass such as
[SecureUxTheme](https://github.com/namazso/SecureUxTheme) or the Windhawk
UXTheme hook — tools that patch system theme validation and can break on
feature updates. Out of scope here by design.

So: you can get the wallpaper, the mode, the accent and the terminal. You
cannot get Wes-Anderson-pink window borders without third-party patching.

## Install

```powershell
# Grand Budapest is light-first, so -Mode defaults to light for that variant
.\apply-theme.ps1 -Variant grand-budapest -Mode light

# every other variant defaults to dark
.\apply-theme.ps1 -Variant tron

# see what it would do without doing it
.\apply-theme.ps1 -Variant crow -WhatIf

# undo everything
.\apply-theme.ps1 -Revert
```

The script copies the wallpaper and `.theme` into
`%LOCALAPPDATA%\Microsoft\Windows\Themes\NeonMary\`, imports the accent
registry values, opens the theme so Windows adopts it, and restarts Explorer
so the taskbar repaints. Every change is under `HKCU` — nothing system-wide,
nothing patched.

`Get-Help .\apply-theme.ps1 -Full` documents the parameters.

## Applying by hand

If you would rather not run the script:

1. Copy the variant's `wallpapers/<variant>/<mode>/4k.png` and the matching
   `<variant>-<mode>.theme` into
   `%LOCALAPPDATA%\Microsoft\Windows\Themes\NeonMary\`, renaming the image to
   `<variant>-<mode>.jpg` to match the path inside the `.theme`.
2. Double-click the `.theme`.
3. Double-click `<variant>-<mode>.reg` for the accent colour.
4. Sign out and back in, or restart Explorer.

## File reference

- `<variant>-<mode>.theme` — INI per the
  [Microsoft theme file spec](https://learn.microsoft.com/en-us/windows/win32/controls/themesfileformat-overview).
  Sets wallpaper, mode, and the legacy `[Control Panel\Colors]` table.

  Worth knowing: `[Control Panel\Colors]` only governs classic and
  high-contrast surfaces. On a default Windows 11 install most of those keys
  are inert — the modern shell does not read them. They are filled in
  coherently anyway so High Contrast and classic dialogs stay on-palette.

- `<variant>-<mode>.reg` — the part that genuinely tints Windows 11 chrome.
  - `AccentPalette`: 32 bytes, eight `BGR0` quads running dark → light. Index
    5 is the primary accent.
  - `AccentColorMenu` / `StartColorMenu` / DWM keys: `0xAABBGGRR` DWORDs —
    note red and blue are swapped relative to HTML hex.
  - `AppsUseLightTheme` / `SystemUsesLightTheme`: mode.
  - `ColorPrevalence`: accent on taskbar and title bars.

Both are regenerated by `../generate_windows.py` and checked by
`../validate_windows.py`, which decodes the byte blobs back and asserts they
match the source palette.

## Windows Terminal

Separate from the system theme. Copy the scheme object from
`../terminals/<variant>/<mode>/windows-terminal.json` into the `schemes`
array in Windows Terminal's `settings.json`, then set it as the profile's
`colorScheme`.
